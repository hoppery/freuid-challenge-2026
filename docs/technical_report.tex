\begin{abstract}
The FREUID Challenge 2026 requires a scalar fraud score in $[0,1]$ for each identity-document image, ranked
by the FREUID Score (AuDET $+$ APCER@1\%BPCER; lower is better). The test data is split by design: the
public split (about $5\%$) is born-digital, while the private split (about $95\%$) decides the ranking and
mixes synthetic and physically captured images, including two document types absent from training. A single
submission is scored on both splits, and the FREUID Score heavily penalizes a model that collapses on part
of the data. We therefore submit one model built for the captured and
unseen-type private split, not one tuned for the public leaderboard. The submitted model is a Double-Trace
Consistency (DTC) capture ensemble: each detector adds a high-pass forensic branch to a pretrained RGB
backbone and uses the trace as a global feature and as a document-type-agnostic patch-consistency signal.
The main gain comes from ensembling decorrelated backbones across architecture and resolution: adding a
RegNetY-160 to two ViT-B detectors lowers the held-out captured-proxy score from $0.384$ to $0.227$. A
public-leaderboard-tuned ensemble reaches $0.00041$ on the public split but is near chance on captured data,
so we do not submit it. Training uses the competition data and public external datasets with self-supervised
augmentation, never the test data; inference is a plain probability average in a pinned container that runs
offline.
\end{abstract}

\section{Introduction}
\label{sec:intro}
Identity-document fraud has several threat models: physical manipulation and re-capture, localized digital
editing, and fully synthetic (GenAI) content. The FREUID Challenge~\cite{freuid2026} combines these into a
single task. The model outputs $P(\text{fraudulent})\in[0,1]$ for each image, scored by the FREUID Score
(AuDET $+$ APCER@1\%BPCER; lower is better).

The challenge splits the test data in a deliberate way. The \emph{public} split is about $5\%$ of the test
data. It is born-digital and covers the five training document types. The \emph{private} split is about
$95\%$ and decides the full ranking. It is drawn from a hybrid of synthetic and physically captured images,
and it adds \textbf{two document types that are not in training}. A detector that only memorizes the
born-digital appearance of the seen types generalizes poorly to the captured and unseen-type content. The
organizers also caution against optimizing the public leaderboard~\cite{freuid2026}.

A single submission is scored on both splits. We cannot produce different predictions for the two splits,
and per-image routing is unsafe (Section~\ref{sec:rejected}). We
therefore submit one model. Section~\ref{sec:antagonism} shows why we do not submit the public-optimized
model: it drops to near chance on captured data. Because the
private split carries captured and unseen-type content, and because the metric heavily penalizes a model
that collapses on part of the data, we submit a model built for robustness (our \textbf{private-best} model). We
select it on a captured proxy, never on private labels.

\paragraph{Contributions.}
\begin{enumerate}[leftmargin=1.3em,itemsep=1pt,topsep=2pt]
  \item We show that a model optimized for the born-digital public leaderboard collapses on captured data
        (Section~\ref{sec:antagonism}); a strong public score therefore need not carry over to the captured,
        unseen-type private split that decides the ranking.
  \item We propose the Double-Trace Consistency detector (DTC), a detector whose patch-consistency signal
        does not depend on the document type (Section~\ref{sec:dtc}, Fig.~\ref{fig:arch}).
  \item We show a diversity-axis ensembling principle: combining decorrelated architectures and resolutions
        improves the submitted ensemble, with the architecture axis giving the larger gain
        (Sections~\ref{sec:diversity}, \ref{sec:results}).
\end{enumerate}

\paragraph{Related work.}
Identity-document forgery and presentation-attack detection is an active benchmark area. FantasyID%
~\cite{fantasyid} provides captured bona-fide cards with GenAI manipulations, close to this challenge's
threat model. For synthetic (GenAI) content, adapter-based detectors on frozen vision-language features
generalize across generators~\cite{fatformer}. Manipulation and re-capture leave low-level traces that
semantic features miss. High-pass residual streams
expose splicing and reprint artifacts. Central Difference Convolutions capture the gradient micro-texture
used in face anti-spoofing~\cite{cdcn}. We build on the residual-trace idea, but we summarize it as a
\emph{consistency} statistic. Self-blended images~\cite{sbi} synthesize manipulation traces without
manipulation labels. We adopt this idea for our self-supervised consistency target and for the field-tamper
augmentation. We use self-supervised ViT features (DINOv2~\cite{dinov2}, ViT~\cite{vit}) together with
a convolutional family (RegNet~\cite{regnet}) through \texttt{timm}~\cite{timm}. These families have different inductive biases, which we use for decorrelation. For
robustness we use Fourier Domain Adaptation~\cite{fda} to randomize low-frequency appearance. Our
ensembling builds on deep ensembles~\cite{deepensembles}; we add evidence on which type of diversity helps
here.

\section{Method}
\label{sec:method}

\subsection{Overview and problem setting}
\label{sec:setting}
Let $x$ be an image and $y\in\{0,1\}$ its fraud label. Each detector produces a fraud logit $\ell(x)$ and a
probability $\sigma(\ell(x))\in[0,1]$, where $\sigma$ is the sigmoid; the submitted score is the mean of the
detectors' probabilities (Section~\ref{sec:calib}). The FREUID training data is born-digital and covers the
seen document types; we augment it with external captured data (Section~\ref{sec:data}). Evaluation uses a
public split $\mathcal{D}_{\text{pub}}$ (born-digital) and a private split $\mathcal{D}_{\text{prv}}$ shifted
in acquisition (captured vs.\ born-digital) and label space (two unseen document types).
$\mathcal{D}_{\text{prv}}$ is not available, and it conflicts with $\mathcal{D}_{\text{pub}}$
(Section~\ref{sec:antagonism}): a model tuned for one split is weak on the other. We therefore submit one
model built for the private split (Section~\ref{sec:models}). Every detector uses the same feed-forward
pipeline: decode $\rightarrow$ resize with ImageNet normalization $\rightarrow$ DTC detector $\rightarrow$
sigmoid.

\subsection{Double-Trace Consistency detector}
\label{sec:dtc}
Each detector (Fig.~\ref{fig:arch}) combines an ImageNet/DINOv2-pretrained RGB backbone with a forensic
branch. The forensic branch applies a Gaussian high-pass residual and a small strided CNN
(\texttt{TraceEncoder}) that keeps the spatial layout. It produces (i) a global trace feature and (ii) an
$8\times8$ grid of L2-normalized patch trace embeddings $\{z_i\}$. We take the off-diagonal pairwise cosine
similarities of $\{z_i\}$ and compute a 7-dimensional \textbf{consistency statistic} $s(x)$ (mean, standard
deviation, minimum, low percentiles, and per-patch max-similarity summaries). The name comes from the two
uses of the high-pass trace: the global trace feature and the patch-level consistency signal $s(x)$. A
design assumption is that a
genuine capture, even a legitimately re-captured one, is uniformly traced, while a locally edited and
reprinted forgery is not. Because $s(x)$ does not depend on the document type, an unseen-type genuine
document should not be flagged merely for looking unfamiliar. The fraud logit $\ell(x)$ is an MLP over
$[\,\text{RGB feature}\,;\,\text{global trace}\,;\,s(x)\,]$
($\text{Linear}\!\rightarrow\!512\!\rightarrow\!\text{GELU}\!\rightarrow\!\text{Dropout}(0.1)\!\rightarrow\!\text{Linear}\!\rightarrow\!1$).
An auxiliary head on $s(x)$ is trained on self-supervised \texttt{TraceMix} coherent/incoherent labels,
which are independent of the fraud label. The branch does not depend on the backbone, so any RGB family can
host it. Training minimizes the binary cross-entropy on the fraud logit plus $\lambda_{\text{dtc}}$ times the
same loss on the auxiliary consistency logit, with $\lambda_{\text{dtc}}=0.5$. We optimize with AdamW and a cosine schedule for three epochs in mixed
precision; the ViT-B backbones are frozen except their last two blocks, and the RegNetY backbone is fully
fine-tuned (Appendix~\ref{app:hparams}).

\subsection{Capture robustness from data and augmentation}
\label{sec:capture}
In our experiments, robustness to captured documents came from \emph{data and augmentation} rather than from
the architecture or loss changes we tried (Section~\ref{sec:rejected}). The private-best models train on FREUID plus diverse external
captured corpora (Section~\ref{sec:data}) with heavy print-and-capture augmentation and FDA domain
randomization~\cite{fda}. With probability $0.4$ we swap the low-frequency amplitude spectrum of an image
with a donor of a \emph{different} document type ($\beta\in[0.01,0.08]$). This randomizes the type
appearance and keeps the forensic phase.

\subsection{Diversity-axis ensembling}
\label{sec:diversity}
A single capture detector is limited. The gain comes from averaging backbones that are \emph{decorrelated}
across two axes: input resolution and architecture family. The two ViT-B detectors at $896$ and $1120$\,px
are strongly correlated (Spearman $\rho=0.79$ on the proxy). RegNetY-160 at $1120$\,px, a different
architecture family, is less correlated with each ViT-B ($\rho=0.69$ and $0.73$) and gives the largest
ensemble gain (Fig.~\ref{fig:ladder}).

\subsection{The submitted model}
\label{sec:models}
We submit one model, the \textbf{private-best} ensemble: a probability average of three DTC detectors
selected on the captured proxy, ViT-B/14 DINOv2 at $896$ and $1120$\,px and RegNetY-160 at $1120$\,px.
RegNetY-160 is the strongest single detector on the proxy ($0.264$) and the least correlated with the two
ViT-B detectors, so it contributes the largest ensemble gain (Section~\ref{sec:private-abl}). This is the
model shipped in the reproducibility container.

As a reference only, we also build a \textbf{public-best} ensemble with a field-tamper augmentation. It
reaches a low public score but collapses on captured data (Section~\ref{sec:antagonism}), so we do not
submit it.

\subsection{Score calibration}
\label{sec:calib}
Each detector outputs a fraud logit. A sigmoid maps it to a per-model probability. The submission score is
the arithmetic mean of the ensemble probabilities. We apply no temperature or learned calibration, and no
post-processing differs between train and test time. Unreadable images are assigned $0.5$, so every input
gives exactly one finite score in $[0,1]$.

\section{Data}
\label{sec:data}
We use the official FREUID \texttt{train/} images and \texttt{train.csv} metadata (Kaggle competition
\texttt{the-freuid-challenge-2026-ijcai-ecai}). The private-best models also train on external
data, combined with FREUID into a single manifest. Four corpora contribute \emph{genuine} captured documents
only: MIDV-500~\cite{midv500}, MIDV-2019~\cite{midv2019}, MIDV-Holo~\cite{midvholo}, and
BID~\cite{bid} (Brazilian CNH/RG/CPF photographs). FantasyID~\cite{fantasyid}
(Idiap), a dataset of fantasy ID cards, contributes both captured-genuine images and GenAI attack images
(face-swap and text edits), so it also adds externally labeled fraud examples. All corpora are used under
their public research licenses, and the pretrained weights under their upstream licenses.

\paragraph{Validation.} The public leaderboard reflects the born-digital distribution, so it does not
predict the captured private set (Section~\ref{sec:antagonism}). For model selection we use a held-out
FantasyID subset of $1{,}295$ images ($465$ genuine captured cards and $830$ GenAI-manipulated versions). It
has no image overlap with the training data, so selection is not leaked. We use FantasyID because its
captured genuine cards and non-training document styles match the two stated properties of the private test
(Section~\ref{sec:intro}). However, FantasyID is also a training source, so this is an
\emph{in-distribution} held-out estimate, not a cross-corpus test. It measures generalization to unseen
FantasyID images and likely overestimates performance on a genuinely new corpus such as the private set. FantasyID is not an organizer-recommended proxy, and we do not claim it shares the private
set's distribution. We read its FREUID score as an indicative held-out number, not a lower bound. We also
hold out a random $10\%$ split of the training manifest for logging. The private set is not available at
submission time, so proxy selection is the only option.

\section{Inference}
\label{sec:inference}
The container entrypoint indexes a flat directory of images. It runs the three checkpoints (build with
\texttt{pretrained=False}, load embedded weights, forward pass, sigmoid) and writes the per-image
probability average as \texttt{id,label}. Test-time preprocessing is a plain resize to the native
resolution with ImageNet normalization. The deployed models use no tiling, no multi-crop, and no test-time
augmentation. The device is CUDA if available, else CPU. The per-model batch size follows the training
config. Unreadable images are assigned $0.5$. The exact command is in Section~\ref{sec:repro}.

\subsection{Public and captured performance}
\label{sec:antagonism}
Fig.~\ref{fig:antagonism} plots each model on both distributions. The two lines cross. The public-best
model is strong on born-digital data ($0.00041$) but at chance on captured data (about $0.99$; a random
classifier scores about $0.99$ on APCER@1\%BPCER). A likely reason is that the public-best model relies on
born-digital forensic cues (fine editing traces, JPEG discontinuities) that print-and-capture re-acquisition
overwrites, so they no longer separate genuine from fraud. The private-best model shows the opposite order.
The gap between the two models is about $400\times$ on the public set, and the order fully reverses on the
captured proxy. A single model therefore cannot serve both distributions well, and the public score does not
predict captured performance. The
private-best model stays well above chance on born-digital data ($0.169$), so it is our submitted model: it
does not collapse on either split, and it is the stronger choice on the captured and unseen-type content
that the private split contains and the public split does not.

\subsection{Rejected approaches}
\label{sec:rejected}
We also tested approaches that did not help, and we dropped them. Submitting the public-best ensemble on
captured data was capture-blind (about chance). Adding MIDV-2020 to the capture mix gave no gain, because
of a distribution mismatch. A learned domain router keyed on framing and context, and it misrouted cropped
captured images. Warm-starting the capture model from the public-best checkpoint gave a worse peak than
training from scratch. Architecture and loss levers on the capture axis
(focal loss~\cite{focal}, CDC convolutions~\cite{cdcn}, MixStyle~\cite{mixstyle}) did worse than the
data-diversity recipe.

\section{Reproducibility}
\label{sec:repro}
The reproducibility container ships the private-best model. The three checkpoints are fetched from a GitHub
Release at build time (SHA-256 verified) and baked into the image, and the models build with
\texttt{pretrained=False}. The container therefore runs with \texttt{--network none} (no runtime downloads)
and writes only to \texttt{/submissions}.
\begin{itemize}[leftmargin=1.2em,itemsep=1pt,topsep=2pt]
  \item \textbf{Environment (pinned):} \texttt{torch==2.12.0} (CUDA 13), \texttt{timm==1.0.27},
        \texttt{albumentations==2.0.8}, \texttt{opencv-python-headless==4.13.0.92}, \texttt{numpy==2.4.6},
        \texttt{pandas==3.0.3}, \texttt{scipy==1.17.1}, \texttt{scikit-learn==1.9.0},
        \texttt{pillow==12.2.0}, \texttt{pyyaml==6.0.3}, \texttt{pyarrow==24.0.0}; Python $\geq 3.11$.
  \item \textbf{Hardware / runtime:} training on $2\times$ NVIDIA RTX PRO 6000 (Blackwell, 96\,GB);
        inference uses a single GPU (about $1.6$\,h for the three models over the full test set on our
        hardware; CPU fallback works but is slow). The base image targets CUDA 13; on a host with an older
        driver, adjust the base tag and the \texttt{torch} index (weights are torch-version portable).
  \item \textbf{Randomness:} global seed $42$. CUDA/cuDNN and AMP add minor non-determinism, within the
        proxy's seed noise.
  \item \textbf{Repository:} \url{https://github.com/hoppery/freuid-challenge-2026} (MIT license; the frozen
        commit SHA is in our reproducibility reply).
\end{itemize}
